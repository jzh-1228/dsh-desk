## 4. 常用命令（仓库根目录）

| 命令 | 用途 |
|---|---|
| `pnpm run dev:desktop` | **开发主命令**：构建（全仓 lib + 桌面）→ 准备运行时 → 启动 Electron |
| `pnpm run start:desktop` | 跳过构建，直接启动上次产物（改完 ts 后需重新 dev 或手动 build） |
| `pnpm run build:desktop` | 只构建桌面壳（tsc -b && tsdown） |
| `pnpm run prepare:desktop` | 仅准备打包资源后停止（诊断） |
| `pnpm run package:desktop:win:x64:unsigned` | 未签名 Windows 测试安装包 |
| `pnpm run package:desktop:dir` | 生成可运行目录（免安装包） |
| `pnpm --dir apps/desktop run check:package` | 打包配置检查 |
| `pnpm run typecheck` / `pnpm run lint` | 类型检查 / oxlint（均先构建 host lib） |
| `pnpm run test` | vitest 全量（先构建 native-system） |

## 5. 模型 Provider 配置与 DSH_HOME（重要）

**本机现状**：用户级环境变量 `DSH_HOME=D:\CursorWP\dsh\.dsh`（旧工作区设置，永久生效）。因此本机 dev 与打包版运行**都会读写这个旧 home**——provider（opencode-go 等 4 家）、API Key、历史会话立即可用；官方桌面对 CLI 的隔离只体现在 `profiles/desktop/`（插件激活/运行包/锁互不干扰），产品数据是共享的。

- `settings.yaml`：`llm-pi-ai.providers.*`（provider/模型列表）+ `agent-default-model`（默认 provider/model）
- `.credentials.yaml`：各 provider 的 API Key

**dev 数据目录规则**（`apps/desktop/scripts/dev.ts`）：
- 设了 `DSH_HOME`（本机情况）→ 直接用它
- 未设 → 默认隔离在 `apps/desktop/.desktop-build/development/home/`（本工作区已预置 settings+credentials 副本作为后备）

**想要完全隔离的开发数据**（推荐做破坏性实验时用）：
```bash
# Git Bash：临时指向一个空目录
DSH_HOME=/d/CursorWP/dsh_desk/dev-home pnpm run dev:desktop
# PowerShell
$env:DSH_HOME = "D:\CursorWP\dsh_desk\dev-home"; pnpm run dev:desktop
```
新 provider 的 quickest 路径：编辑对应 home 的 `settings.yaml`（`llm-pi-ai.providers.<id>`，含 `apiKeyEnv` 指向的环境变量名），Key 写入同目录 `.credentials.yaml`。

## 6. 调试

- dev 启动时 DevTools 默认自动打开；关闭：`DSH_DESKTOP_OPEN_DEVTOOLS=0`
- 端口：Main `9229`（`node --inspect` attach）、Renderer `9222`（Chrome 远程调试）、Host `9230`
- 日志：`ELECTRON_ENABLE_LOGGING=1`（dev 默认开）；Host 诊断仅保留 stderr 最后 64 KiB
- 构建产物：壳 `apps/desktop/lib/main.js`，宿主 `apps/desktop-host/lib/index.js`

## 7. 打包发布（Windows）

1. `cp apps/desktop/.env.windows.example apps/desktop/.env.windows` 并填写（签名 Token PIN、更新源等；纯本地测试可先不填，用 unsigned 目标）
2. `pnpm run package:desktop:win:x64:unsigned` → 产物在 `apps/desktop/.desktop-build/targets/win-x64/`
3. 免签名快速验证用 `package:desktop:win:x64:dir` 生成可运行目录
4. 正式签名需 EV 证书 + SafeNet Token（PIN 含 `]`/引号/换行会失败；错 5 次锁死 Token）
5. 上传更新走腾讯 COS（`upload:win:x64`，凭据同样在 `.env.windows`）

## 8. 已知坑位

- `pnpm install` 会出现 `Failed to create bin ... dsh\lib\bin.js.EXE` 警告：`@deepseek-ai/dsh` 尚未构建，正常现象，`dev:desktop` 的构建步骤会补齐
- 首次 `dev:desktop` 会下载 Python primary-runtime（解释器+wheel，见 `apps/desktop/scripts/primary-runtime-lock.json`），耗时视网络
- 未签名构建可能被 Windows 代码完整性策略拦截（任何模式都不关闭该策略）
- 官方 README 提醒：会话格式升级至 V3（v0.1.5-rc.1），旧 `~/.dsh` 数据跨版本升级有迁移逻辑但建议先备份

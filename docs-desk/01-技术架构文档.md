# dsh 官方桌面版 · 技术架构文档

> 基线版本：v0.1.6-alpha.2（upstream commit `ddefc45fbc`）
> 本文档基于官方源码 `apps/desktop` 与 `apps/desktop-host` 整理，供二次开发参考。

## 1. 项目定位

官方桌面版是 **dsh Web 应用外的一层 Electron 薄壳**，不重写 Harness 本身：

- Electron 主进程通过 `ELECTRON_RUN_AS_NODE=1` 以 Node 模式子进程启动 **desktop-host**，后者加载 dsh 的 `desktop` profile 并启动 Web 服务（`127.0.0.1:19387`）
- 窗口从自定义协议 `dsh-app://app/` 加载打包内的 Web 入口，HTTP 请求经壳转发给已认证的 Web Host，WebSocket 流仅对归属窗口附加凭据
- 不依赖系统 Node.js / pnpm / Python：所有包操作使用内置 pnpm，Python 运行时（primary-runtime）随应用分发
- **发布身份强绑定**：Electron 壳与 `@deepseek-ai/dsh` 始终同一精确版本，升级 dsh 必须发布新版桌面安装包

## 2. 三个协作组件

| 组件 | 目录 | 职责 |
|---|---|---|
| Electron 壳 | `apps/desktop` | 窗口/生命周期、自定义协议、单实例锁、更新体系、致命故障恢复 |
| 桌面宿主 | `apps/desktop-host` | 以 Node 子进程运行 `desktop` profile，起 Web 服务、装 Office 插件、上报就绪 URL |
| Web UI | `apps/web` | 完整 dsh 前端（会话/插件/侧边栏等），被壳加载显示 |

底层共享 `packages/` monorepo 的全部能力（core/client/host/llm/mcp/session/skill/pet…）。

## 3. 进程模型与通信

```
Electron main (apps/desktop/src/main.ts)
 ├── BrowserWindow ──加载──> dsh-app://app/  (Web UI)
 │     └─ preload-*.ts 注入桥（app/menu/platform/mandatory/update-dialog）
 ├── 子进程: Electron 二进制 + ELECTRON_RUN_AS_NODE=1
 │     └─ apps/desktop-host/src/index.ts
 │           ├─ runProfile(profile: 'desktop') → Web Server 127.0.0.1:19387
 │           ├─ ctx.plugin(desktopOffice) → office-docx/pptx/xlsx 技能
 │           └─ IPC 上报 { type:'ready', url(已认证), injections }
 ├── DesktopBackendController（HTTP 转发 / WebSocket 凭据附加）
 └── DesktopUpdateCoordinator（electron-updater + Nightly 通道）
```

- **Node IPC 消息**（host ↔ main）：`ready`（就绪+URL）、`fatal`（启动失败）、`shutdown`/`shutdown-complete`、`update-tasks`（inspect/lock/unlock，更新期间锁住 Host 任务）
- **自定义协议 `dsh-app`**（`src/ipc.ts` 中 `SCHEME`）：特权 scheme（standard/secure/supportFetchAPI/corsEnabled/stream），页面源 `dsh-app://app`，壳内建页面 `dsh-app://shell/*.html`（强更页、更新对话框等）
- **默认端口**：桌面 Web Host `19387`（可用 `webserver.config.port` patch 覆盖；Web 独立运行时是 `3080`）

## 4. 安装归属与隔离

- Electron **独占** `$DSH_HOME/profiles/desktop/` profile（含 `lock` 事务锁）；CLI 不能启动或修改该 profile
- 与 CLI **共享** `$DSH_HOME` 下的会话、设置、凭据、工作区等产品数据；**绝不共享**可执行包、插件激活、锁文件、node_modules
- Electron 启动前获取进程单实例锁（`src/single-instance.ts`）；`EADDRINUSE` 时提示退出其他实例

## 5. Electron 壳源码导览（apps/desktop/src）

| 文件 | 职责 |
|---|---|
| `main.ts` | 入口：特权协议注册、窗口创建（Windows 主窗口隐藏标题栏+overlay）、菜单/语言/主题、致命恢复接线 |
| `host-process.ts` | 以 `ELECTRON_RUN_AS_NODE` 拉起 desktop-host 子进程并管理其生命周期 |
| `backend-controller.ts` | Web Host 的 HTTP 转发与 WebSocket 凭据附加 |
| `web-document.ts` | `dsh-app://` 页面服务、Web Host 认证、请求转发 |
| `ipc.ts` | `DESKTOP_IPC` 通道常量与 `SCHEME='dsh-app'` |
| `project-manager.ts` | `$DSH_HOME/profiles/desktop` 的 profile/插件/补丁管理（恢复时可一键禁用全部第三方插件） |
| `fatal-recovery.ts` | 致命失败时的原生恢复对话框：禁插件、备份 profile patch、重启 |
| `single-instance.ts` / `owned-directory.ts` | 单实例锁与独占目录管理 |
| `update-*.ts` | 更新协调器/日志/调度/对话框/强更策略/HTTP 执行器/覆盖层等一族模块 |
| `mandatory-update-*.ts` | 强制更新策略、独立窗口与 IPC |
| `preload-*.ts` | 渲染层桥：app、menu、platform、mandatory、update-dialog |
| `windows-layout.ts` | Windows 标题栏高度等窗口布局常量 |
| `paths.ts` / `locale.ts` / `directory-picker.ts` | 路径解析、多语言消息、原生目录选择器 |

## 6. desktop-host 源码导览（apps/desktop-host/src）

| 文件 | 职责 |
|---|---|
| `index.ts` | 入口：`loadProfileDirectory('dsh', …)` → `runProfile({ profile:'desktop', …, args:['--no-open','--port','19387'] })`；就绪后 IPC 上报认证 URL；实现优雅停机 |
| `office.ts` | Office 技能插件（office-docx/pptx/xlsx），依赖 primary-runtime 的 Python |
| `primary-runtime.ts` | 内置 Python 运行时（numpy/pandas/python-docx/openpyxl 等）管理，首次使用离线安装到 `~/.dsh/dsh-runtimes/dsh-primary-runtime` |
| `update-tasks.ts` | 更新窗口期的 Host 任务锁定控制 |
| `workspace-dependencies.ts` | 工作区依赖（`load_workspace_dependencies`）装载 |

## 7. 更新体系

- 固定 **Nightly 通道**：10 分钟基础间隔 + 20% 抖动，失败指数退避（上限 1 小时）
- 强更策略（mandatory-update-policy）：测试环境飞书鉴权、正式匿名；**第二次用户批准才安装**；Host 收尾失败会拒绝安装并回滚旧版本
- 更新期间通过 `update-tasks` IPC 锁定 Host 任务，更新日志落盘（update-journal）

## 8. 打包链路（Windows 为例）

- electron-builder（`electron-builder.config.mjs` + `.d.mts` 类型），NSIS 安装器（`scripts/installer.nsh` 定制界面）
- 打包输入在 `apps/desktop/.desktop-build/targets/<target>/`，`.desktop-build/downloads` 共享 Electron 归档缓存
- `resources/app.asar/dsh/` 打包 dsh 依赖树 + `desktop-runtime.json` 清单；签名前按 `runtime-file-policy` 过滤 node_modules（保留运行时 JS/原生模块/WASM/许可证）
- Windows EV 签名需 SafeNet 兼容 SignTool + USB Token（`scripts/windows-sign.mjs`）；**未签名测试包**：`package:desktop:win:x64:unsigned`
- 上传走腾讯 COS（`upload-target.ts`，凭据在 `.env.windows`）

## 9. 调试体系

| 目标 | 端口 | 说明 |
|---|---|---|
| Electron Main | 9229 | `--inspect=127.0.0.1:9229` |
| Renderer | 9222 | `--remote-debugging-port`，DevTools 默认自动打开 |
| desktop-host | 9230 | `DSH_DESKTOP_HOST_INSPECT_PORT` |

可用环境变量：`DSH_DESKTOP_MAIN_INSPECT_PORT`、`DSH_DESKTOP_RENDERER_DEBUG_PORT`、`DSH_DESKTOP_HOST_INSPECT_PORT`、`DSH_DESKTOP_OPEN_DEVTOOLS=0`（关闭自动开 DevTools）、`ELECTRON_ENABLE_LOGGING=1`。

## 10. 与社区桌面项目的关系

- 官方桌面版（本仓库 `apps/desktop`）与社区项目 anywhere-labs/dsh-desktop 是**两条独立代码线**；后者以 git 子模块固定官方 harness 版本再做壳，前者壳与引擎同仓同版本发布
- 二开建议直接以本仓库为基线（壳代码官方维护、升级随 upstream master 同步），改动集中在 `apps/desktop/src` 与 `apps/desktop-host/src`
